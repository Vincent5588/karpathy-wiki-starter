# NotebookLM 報告生成 Prompt（v1.3，2026-05-07）

> 此檔案的全部內容會被當作 `studio_create` 的 `custom_prompt` 參數。
> 不要簡化或改寫，這是 skill 的核心。
>
> **版本歷程**：
> - v1（2026-05-07 初版）：字數 2000-5000，重點 10-25，延伸 3-8 → 太冗長
> - v1.1（2026-05-07 收緊）：字數 800-1500，重點 6-12，延伸 2-4 → 偏簡，深度不夠
> - v1.2（2026-05-07 取中）：字數 1200-2500，重點 8-16，延伸 3-5 → 平衡，但對 3 小時 Naval 訪談類長影片 over-compressed
> - **v1.3（2026-05-07 階梯化）**：字數依影片長度動態階梯，重點 8-16 / 延伸 3-5 不變

***

請針對提供的 YouTube 影片來源，產生一份**繁體中文分析報告**。目標讀者是技術 / 商業背景的專業人士，要快速掌握影片核心並能直接引用。

**字數依影片長度動態階梯**：

| 影片長度 | 字數範圍 |
|---------|---------|
| < 10 min | 800-1500 字 |
| 10-30 min | 1500-2500 字 |
| 30-60 min | 2500-4000 字 |
| 60-120 min | 4000-6000 字 |
| > 120 min | 5000-8000 字 |

**判斷規則**：
- 訊息密度高的短教學影片 → 靠上限
- 訪談 / 對話式長影片 → 靠下限（自然有重複，要壓縮）
- 寧可下限不要破上限——3 小時影片 6000 字夠了，不硬塞 8000
- 重點 8-16 條 / 延伸 3-5 條**維持固定**，長影片靠擴展單條深度（每條 3-5 句），不是條數
- 重複的話不要說兩次

## 必須遵守的格式規則

1. **全文繁體中文**（標題、內文、列點全部繁中。簡體中文影片內容也要轉繁中）
2. **英文專有名詞中英對照**：每個英文術語、產品名、人名、公司名第一次出現時，使用 `English（繁中說明）` 或 `繁中（English）` 格式
   - ✅ `Retrieval-Augmented Generation（檢索增強生成，RAG）`
   - ✅ `Anthropic（生產 Claude 的 AI 公司）`
   - ❌ 純英文 `RAG is a technique...`
   - ❌ 純中譯不附原文
   - 例外：純命令 / 程式碼 / 約定俗成不譯的廠商縮寫（如 GitHub、Google、API）
3. **英文影片 quote 加繁中翻譯**，原文 quote 下方緊接著繁中 quote：

   ```
   > "Original English quote from the video."
   >
   > 繁中：「翻譯文字。」
   ```

   中文影片 quote 直接用中文原文即可。

4. 數字、技術參數保留原值
5. 標題用 markdown `##` / `###` / `####`
6. 列點用 `-`，編號清單用 `1.` `2.`
7. **不要在報告開頭寫「以下是」「我為您準備了」這種開場白**，直接進第 1 節
8. **列點不要每條都用 `**bold:**` 開頭**，那是 AI 痕跡

## 報告結構（8 節）

### 1. 影片基本資訊

純資料表，包含：標題 / 頻道 / 發布日期 / 時長 / 演講者 / 影片類型

### 2. 核心論點

**100-200 字** 摘要：
- 作者要傳達的**單一最核心訊息**（一句話）
- 論證主軸（為什麼作者這樣主張）
- 目標受眾

不要在這節列重點，重點留到第 3 節。

### 3. 關鍵重點（**8-16 條**）

條列形式。每條：
- 1-3 句話，講清楚「重點是什麼 + 為什麼重要」
- 含時間戳 `[mm:ss]`
- 包含具體數據 / 例子 / 引言（不只抽象概念）
- 涵蓋反例 / 反論 / 警告（若有）

**重點集中在「對讀者有 actionable 價值」的內容**，但對於資訊密度高的影片可拉到 16 條，覆蓋所有主要小節。

### 4. 重要數據與引言

#### 4.1 數據（**4-6 條**）

每筆：`{指標}：{數值} {單位}` + 出處（演講者 [時間戳]）+ 脈絡（這個數字在比較什麼）

#### 4.2 引言（**3-4 條**）

英文影片：

> "Original quote text."
>
> 繁中：「翻譯。」

— {演講者 [時間戳]}

中文影片直接中文 quote 一次。

### 5. 推論與結論

**3-4 個 bullet**：
- 結論：作者最終立場
- 預測：作者對未來的判斷（標時間範圍）
- 建議：作者給觀眾的具體 action items
- 可選一條反思：論證的薄弱處 / 邊界

### 6. 適用情境

- **誰用得上**：3-4 種具體角色
- **什麼情境**：1-2 句話
- **不適用**：1-2 種情境

### 7. 延伸思考（**3-5 條**）

真正值得追問的問題，不要湊數：
- 作者的論證有哪些未驗證假設？
- 作者沒談到但相關的對立觀點？
- 從這支影片可以延伸出的後續研究方向？
- 在台灣 / IT 維運 / 知識管理場景下，如何在地化應用？

### 8. 來源摘要

#### 8.1 影片連結

每支：`- [{標題}]({YouTube URL}) — {頻道} — {時長}`

⚠️ NotebookLM 目前 100% 不會給正確 URL（11 跑 11 中）— skill 的 humanizer 階段會直接覆蓋成實際 URL。

#### 8.2 章節時間戳目錄（**6-10 條**）

挑主要章節。若 transcript 沒明顯小節，這節寫「無法從 transcript 推斷明顯章節」。

## 品質自檢

產出報告前自問：

- [ ] 8 節都有寫，深度跟簡潔平衡？
- [ ] 第 3 節重點 8-16 條，沒湊數也沒漏主要小節？
- [ ] 英文專有名詞每個第一次出現都有中英對照？
- [ ] 英文 quote 都有繁中翻譯？
- [ ] 沒有 AI 慣用詞濫用：「核心 X」「全面」「綜合」「關鍵」「凸顯」「展現」「奠定」「象徵」？
- [ ] 沒有 rule of three 強行湊三條？
- [ ] 沒有「不只是 X，更是 Y」這種 negative parallelism？
- [ ] 沒有 puffy 標題（譬如「【深度分析報告】...新紀元」）？

如有節資訊不足，**直接標明「資訊不足，原因 XX」**，不要硬掰。
