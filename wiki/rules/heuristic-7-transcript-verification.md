# 經驗法則 7：AI 轉錄二手素材必逐項查證

> **一句話**：AI 轉錄產出的素材**讀起來完全正常，但專有名詞與數字會系統性出錯，而且它還會憑空生出「行動項目」與「決策」**。ingest 前必逐項查證，不可因敘述流暢就放行。

## 適用範圍

**要套用**（凡經語音／影片自動轉換的二手素材）：

- 語音辨識逐字稿（各家 Whisper / ASR）
- YouTube / Podcast 的 AI 摘要（含經驗法則 4 fast-path 的產出）
- 雲端筆記工具產生的分析報告
- AI 會議紀錄工具（各家「智能紀要」）的輸出

**不必套用**：

- 第一手文字素材（官方文件、論文 PDF、自己寫的筆記、網頁原文）
- 使用者自己打字的內容
- 已由人工校對過並註明的轉錄稿

## 為什麼一般的「查證」紀律不夠

vault 已有規則 M.1（要 evidence）與規則 O（引用前必 verify）。但那兩條處理的是「**我不確定的事**」。

**轉錄素材的危險在於：它讀起來完全不像不確定。** 敘述流暢、結構完整、細節具體——**沒有任何訊號提示你該懷疑**。若不主動設一道查證關卡，錯誤會直接流進 vault。

## 兩類必查項目

### A. 專有名詞與數字（語音辨識層的錯誤）

| 錯誤型 | 說明 |
|---|---|
| **同音字** | 中文同音詞極多，ASR 會挑錯字（人名、公司名、產品代號最常見）|
| **數量級** | 量詞與單位被吃掉或聽錯（「十萬」→「十」，差 10⁴）|
| **產品／公司名** | 英文品名、少見公司名最易錯，且錯得很像真的 |
| **修飾語壓縮** | 摘要階段把限定條件砍掉，語意飄移（「選型決策時長縮短 70%」→「效率提升 70% 以上」，方向、範圍、程度三重失真）|

### B. AI 生成的虛構結構（摘要層的幻覺）

會議紀錄類工具常有「決策 / 行動項目 / 負責人 / 截止日」的固定模板。**當原始素材裡沒有這些東西時，工具會自己編。**

**辨識訊號**（看到就該警覺）：

- 日期非常具體，但**負責人全是 `[填寫空白]` / `[待填]`**
- 素材通篇是單人論述（演講、影片），卻產出「跨部門共識」「與會者決議」
- 行動項目的顆粒度過於工整（每項都有理由 + 範圍 + 里程碑）
- 大量模板佔位符殘留

**處置**：**整段排除，不 ingest**。並在 entity 的 `## 待解` 註明「原文含 AI 生成之樣板行動項目，未採用」。

> ⚠️ **為什麼不能「先寫進去之後再改」**：若照抄，未來查 wiki 會讀到「本單位決議設立 X 工作組、Y 日前完成 Z」——**完全虛構的組織承諾，而且看不出是虛構的**。

## 執行 SOP

```
1. 判定素材是否為 AI 轉錄產出
   ├─ 檔名含 -Summary / -逐字稿 / -紀要
   ├─ 內文有 [填寫空白] / [待填] 等佔位符
   └─ 出現不該存在的東西（影片開場白、口誤註記）→ 強訊號
2. 若是 → 列出所有「專有名詞 + 數字」清單
3. 逐項獨立查證（優先官方新聞稿 / 論文 / 一手來源，避開內容農場）
4. 掃描「決策 / 行動項目 / 負責人 / 日期」區塊 → 套用 B 類辨識訊號
5. 在 entity 內建「查證更正表」（原文 → 實際 → 錯誤類型）
6. chat 報告時主動說明查到幾處錯誤
```

## 為什麼要保留「更正表」而不是默默改掉

在 entity 裡留一張 `原文 → 實際 → 類型` 的對照表，有三個作用：

1. **讓未來的自己知道這份素材不可信**——下次從同一來源 ingest 會提高警覺
2. **若查證本身有誤，可回溯**
3. **原始檔仍在 PARA 裡**，若有人直接讀原始檔，更正表是唯一的交叉檢查點

配套：該素材所在 PARA 資料夾的 `README.md` 也應標註可信度與更正指向。

## 與其他規則的關係

- **經驗法則 4**（YT fast-path）— 該法則產出的正是本法則要查證的素材類型。**兩者配套**：4 負責快速產出、7 負責把關品質。
- **規則 K**（raw 預檢）— Step 0 應加入「是否為 AI 轉錄產出」的判定分支。
- **規則 M.1 / M.4** — 本法則是它們在特定素材類型上的具體化（M 講「要 evidence、不要推論」，本法則講「這類素材必須**主動去要** evidence」）。
- **經驗法則 6**（廠商內容立場標註）— 兩者常同時觸發：轉錄素材若來自廠商／機構發言人，**既要查證數字也要標立場**。
